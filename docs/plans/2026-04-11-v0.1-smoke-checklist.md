# OE3 v0.1 End-to-End Smoke Checklist

Walk this checklist against the live docker compose stack before tagging v0.1.0.
Mark each item `[x]` when verified. Any failure must be fixed — do not skip.

---

## 1. Stack startup

- [ ] `docker compose -f docker-compose.dev.yml up -d`
- [ ] All three containers reach healthy status within 60 s:
  - `docker compose -f docker-compose.dev.yml ps` shows `(healthy)` for `postgres`, `orthanc`, `azure-emulator`

## 2. Seed sample data

- [ ] `docker compose -f docker-compose.dev.yml --profile seed up seeder`
- [ ] Seeder output ends with `Seed complete`
- [ ] `curl -s http://localhost:8042/studies | jq length` returns ≥ 1

## 3. App boots without errors

- [ ] `npm run dev` (or `bun run dev`) starts without error
- [ ] Browser loads `http://localhost:5173` without red console errors
- [ ] No Zod validation errors in console (`window.__OE3_CONFIG__` populated cleanly)

## 4. Runtime config

- [ ] In browser devtools: `window.__OE3_CONFIG__` returns the expected object
  (e.g. `{ orthancUrl: "...", authMode: "none", features: {} }`)
- [ ] Config shape validates without throwing

## 5. Study list — real data

- [ ] Study list page shows ≥ 1 study (the seeded sample)
- [ ] Patient name / date / modality columns populate from real Orthanc data
- [ ] Search / filter controls run a real `/tools/find` POST (confirm in Network tab: method=POST, body contains `Level:"Study"`)

## 6. Study detail — real series data

- [ ] Click a study row → detail page opens
- [ ] Series panel lists real series from `/studies/{id}/series`
- [ ] No "undefined" or `[object Object]` in any field

## 7. Upload — drag-drop

- [ ] Navigate to Upload page
- [ ] Drag `test-data/sample.dcm` onto the drop zone
- [ ] Upload completes and reports success
- [ ] Network tab shows POST to `/instances` with `Content-Type: application/dicom`

## 8. Activity timeline — live polling

- [ ] Navigate to Activity page
- [ ] Timeline shows recent change events (populated from `/changes` — may be empty if no recent operations; trigger one by navigating the study list)
- [ ] Network tab shows periodic GET `/changes?limit=100` requests (~every 5 s)

## 9. Settings → Modalities CRUD + C-Echo

- [ ] Navigate to Settings → Modalities tab
- [ ] Add a dummy modality (e.g. AET: `TEST`, Host: `127.0.0.1`, Port: `11112`)
- [ ] Modality appears in the list from real `/modalities` endpoint
- [ ] C-Echo button fires POST `/modalities/TEST/echo` — expect a failure toast (no real DICOM server at that address is correct behavior)
- [ ] Delete button removes the modality

## 10. Settings → System info

- [ ] Navigate to Settings → System tab
- [ ] Server name shows `OE3 Dev`
- [ ] Orthanc version is populated
- [ ] Plugin list is non-empty (shows loaded plugins)

## 11. Delete study action — audit trail

- [ ] Navigate to a study detail page
- [ ] Click Delete (confirm if prompted)
- [ ] Browser devtools console shows a log entry with:
  - `action: "study.delete"`
  - `outcome: "success"`
- [ ] Study list no longer shows the deleted study (React Query cache invalidated)

> **Note:** Re-seed before continuing: `docker compose -f docker-compose.dev.yml --profile seed up seeder`

## 12. Health banner — Orthanc outage simulation

- [ ] Stop the Orthanc container: `docker stop orthanc-explorer-3-orthanc-1` (adjust container name as needed)
- [ ] Within ~15 s (3 consecutive polling failures), the global health banner appears with the degraded message
- [ ] No PHI visible in the banner text

## 13. Health banner — recovery

- [ ] Restart Orthanc: `docker start orthanc-explorer-3-orthanc-1`
- [ ] On next successful API response, the health banner disappears

---

## Done criteria

All 13 items checked with no unresolved failures.
If any item fails, open a follow-up task before tagging v0.1.0.
